# Versioned collections and record writes (STA-7)

The regional `CollectionRegistry` accepts one closed Draft 2020-12 schema per collection version. The owner defines a collection; an owner or a current collection grant with `schema:write` may revise it. The registry returns the active definition and separates ready indexes from pending declarations. A collection update requires the exact prior version. Existing field constraints, unique declarations and lifecycle rules cannot change in v1. New optional top-level fields, descriptions and filter/sort declarations are compatible. An unsupported keyword is `SCHEMA_UNSUPPORTED`; a changed constraint is `SCHEMA_BREAKING` with the affected field in the error where possible.

`PostgresAuthority.mutateRequest` is the validated mutation entrypoint for a trusted, authenticated regional scope. It accepts create, replace, top-level patch and tombstone delete. Existing-record mutations require `expectedRevision`; a conflict exposes only the current revision. It derives the request fingerprint, canonical JSON, unique tuples and typed index values itself. Clients cannot pass precomputed reservations or indexes through this entrypoint. Optional lifecycle data declares `{field, initial, transitions}` over a string enum; no collection name has special meaning. The preexisting `mutate`/`AuthorityTransaction.mutate` adapter methods are low-level test/qualification hooks and must not be exposed by a transport. Regional routing and credential verification remain the responsibility of `PostgresCellPolicy`; callers must never derive `AuthorityScope` from user-selected IDs or claims.

Node accepts in-process objects only when `node:util.types.isProxy` is present. [Cloudflare Workers does not currently implement that detector](https://developers.cloudflare.com/workers/runtime-apis/nodejs/util/), so regional Workers must use `defineSerialized`, `reviseSerialized` and `mutateSerializedRequest` with primitive JSON text. Those methods parse after scope authorization and validate the resulting ordinary data. For routed cell writes, call `context.records(authority, tx => tx.mutateSerializedRequest(bytes))` so the credential and placement fences enclose the mutation commit. Object entrypoints fail closed when the detector is unavailable. This boundary is locally tested with serialized requests; a deployed Worker remains an external acceptance check.

The collection row is locked in shared mode from validation through commit. Schema revision takes an exclusive lock on that row. This serializes a write with a concurrent version switch and assigns one accepted schema version to the receipt, event and record. The record row's conditional revision update serializes competing writers. A no-op patch or replacement still advances revision and commits a receipt, event and outbox entry. A tombstone retains external and composite unique reservations, but removes typed filter values; generated IDs are never reused. Explicit null and missing fields do not reserve composite tuples. External keys use NFC then the v1 fixed Unicode White_Space trim, including U+0085 but excluding U+FEFF. Stored data spelling is preserved.

New typed index declarations start `ready=false`. `CollectionRegistry.backfill` commits at most 100 live record rows and a cursor per call, and sets `ready=true` only with its final batch. Writes after the declaration maintain that index in their mutation transaction. Exact predicate calls reject an undeclared, unready or nonfilterable field with `SCHEMA_CONFLICT`; they never report a partial indexed result as complete. STA-8 owns public query allowlists, cursors, sort and aggregate behavior.

Operational guards in this slice: a canonical definition or record is at most 1 MiB, matching the existing authority column check and canonical record admission; JSON nesting is capped at 32 nodes deep and a definition at 256 schema nodes to bound recursive work. The 100-row backfill unit limits one transaction's lock and query span. These are protective configuration choices, not measured capacity or latency promises. Receipt retention is supplied to `PostgresAuthority` at construction; clients must use the configured retry window. UTC leap-second validation follows the positive-date list through [IERS Bulletin C 72](https://datacenter.iers.org/data/html/bulletinc-072.html), current at implementation; future bulletins must be checked before deployment updates.

Focused local evidence is `test/integration/collections.test.js` against a disposable Postgres cluster. It tests incompatible definitions, normalized and typed reservations, revision and schema races, replay, rollback, tombstones, declared lifecycle transitions and a 101-row partial backfill. Railway Postgres and Cloudflare Preview integration, authenticated provider and Aside Browser journeys are not certified by that local suite. STA-21 is the configured live regional acceptance gate; future transport issues must also verify their own public envelopes and UI behavior.
