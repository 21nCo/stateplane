# Exact queries and bounded ingestion (STA-8)

The regional authority owns exact collection reads. `getRecord(id)` and `getByKey(mode,key)` resolve scoped IDs and normalized keys; `countRecords` and `existsRecord` use SQL over `records` and declared typed index values. They never use recall or semantic candidates. The regional caller must supply a server-derived, authenticated `AuthorityScope`; scope checks hold the space and collection policy locks through the transaction. A Worker without trap-free proxy detection uses `querySerializedPage`, `countSerializedRecords` and `existsSerializedRecord` with primitive JSON strings. Do not expose the low-level `queryRecords` or `mutate` hooks as public transport endpoints.

`queryPage(predicates,limit,sort?,cursor?)` accepts an AND list of up to 16 typed comparisons. Each `in` list has 1–16 values of the declared scalar kind. Every field must have a ready, filterable declaration; a sort field must have a ready, sortable declaration. The compiler always includes space, collection and live-record predicates. An explicit ascending sort orders missing, explicit null, then present values; descending reverses that primary order. Equal ranks and values use `record_id ASC`. Omitted sort uses `(created_at,record_id)`. Each page returns at most 100 records and 2,097,152 canonical-data bytes. The SQL limits each present/null/missing metadata branch to 101 rows, ranks at most 101 combined candidates and fetches only rows within the byte budget in the same statement snapshot. Every declared filter or sort field has an indexed `missing` projection row for an absent value. Sort-only pages first take bounded keys from the typed and presence indexes, then fetch record bytes; filters retain their authoritative record predicate checks. A five-second database statement timeout bounds exact queries. Every standalone authority transaction starts a 30-second request budget before pool admission, shared by authorization, index checks and SQL. A regional cell starts one 30-second budget before routing nonce admission; it covers cell pool admission, policy SQL, provider authorization elapsed time, the application callback, every joined record operation, and final commit checks. Sequential joined calls cannot restart that clock. An expired budget before COMMIT returns `RATE_LIMITED`, rolls back the cell transaction and exposes no joined receipt. If a sent COMMIT misses its acknowledgement deadline, the result is `CommitOutcomeUnknownError`; the pending receipt remains hidden because the database may still commit. Nonce admission commits separately; an expiry before its COMMIT may roll that nonce back, while a committed nonce remains consumed. In all cases obtain a fresh routing assertion and retry with the same record idempotency key to resolve the authoritative receipt. The cell closes its records context when the callback deadline expires; an external effect already started by application code still needs its own cancellation boundary. The old `queryRecords` method also caps payload bytes but has no continuation token.

The constructor's third argument is a private `Uint8Array` cursor key of at least 32 bytes, supplied by the cell's private binding. Do not log or return that key. An AES-GCM authenticated, encrypted cursor binds the space, collection, principal, credential, policy version, placement generation, schema version, predicate/sort/limit digest, last key and 15-minute expiry. Rotation invalidates outstanding cursors. A malformed, noncanonical, expired, changed or cross-scope cursor returns `CURSOR_INVALID`. A page is exact at its own SQL statement, but consecutive pages are **live traversal**, not a complete snapshot. Deletes can remove unseen rows; inserts before the cursor can be missed. A mutable sort value moving before or after the cursor can skip or repeat a record. Consumers that need a fixed export must use a separately designed snapshot/export boundary.

`ingestBatch(scope,operationKey,serializedRequests,retryFailed?)` accepts 1–20 item JSON strings with a total of at most 2,097,152 UTF-8 bytes. Workers without proxy detection use `ingestSerializedBatch` with a JSON array string. Items omit `idempotencyKey`; Stateplane derives one from authenticated scope, operation key and ordinal. A manifest is committed before any item. The manifest digest and item texts are immutable for that operation key; a changed retry returns `BATCH_CONFLICT`. Every item commits its record/event/outbox, durable status and canonical receipt in one authority transaction. A failed item rolls back on its own, receives a stable failure code and leaves successful items intact. Retry the **same** manifest with `retryFailed=true` after fixing the cause; without it, only pending items run. `batchProgress` returns ordinal statuses, attempts, failure codes and receipts to the same credential with a current record read or write grant. `cancelBatch` stops future items and serializes with in-flight item commits; if the lock exceeds 100 ms it returns `BACKPRESSURE` for a later retry. Successful receipts remain. A lost COMMIT acknowledgement is ambiguous and must be retried with the same operation and manifest. The operation ledger survives ordinary receipt expiry and is erased with its space. One 30-second ingest request budget starts before serialized preflight or manifest validation and covers pool admission, authorization and SQL through final progress. If it expires before all items settle, the ingest call returns `RATE_LIMITED` without an inline progress body; call `batchProgress` with the same scope and operation key to read durable partial status, then retry the unchanged operation and manifest to resume pending items. Once every item has settled, the final progress read gets a fresh bounded read budget so a late clock tick cannot turn a fully committed batch into a reported partial timeout. If the manifest never committed, progress returns `NOT_FOUND` and the original operation can be retried. An item statement is bounded by its remaining budget or 15 seconds, whichever is shorter. `BACKPRESSURE` also means all eight per-collection write slots are held or an item transaction rolled back under a transient serialization/deadlock; retry the unchanged operation and manifest. `RATE_LIMITED` indicates a byte or time budget.

These are initial protective limits, not measured Railway or Hyperdrive capacity. The focused local PostgreSQL 16/pgvector test seeds 5,000 synthetic rows and checks `EXPLAIN (ANALYZE, BUFFERS)` for selective typed pages and sort-only pages in both directions. Number, string, boolean and date-time sort plans must use their typed index plus `record_index_missing`, avoid sequential scans of `records` and `record_index_values`, and stay below 2,000 shared-hit blocks for a 25-row page. This is a local plan budget, not a Railway latency guarantee. The suite also verifies 750,000-byte record pages stop at the 2 MiB budget, interrupted manifests, receipt replay, failed-item retry after schema repair, transient rollback recovery, cancellation, cross-scope/query/schema/credential cursors, mutable sort movement and ninth-writer backpressure. The 100-row page and 16-index-field limits match the existing backfill/query bounds; the 20-item/2 MiB batch and eight-slot write limits keep one request's memory and concurrent transaction locks bounded. Re-measure plans and latency in the target regional Railway database before increasing any limit. On a disposable local PostgreSQL 16 database with 16 declared number projections, one create used 22 authority SQL statements and 2 timeout-setting statements in 14 ms; one replace used 25 and 2 in 4 ms; a 20-item batch used 560 and 45 in 78 ms and left 336 projection rows for 21 live records. The prior per-statement timeout implementation used 39/19 for create, 45/22 for replace, and 1008/493 for the same batch, measured on the same host. Standalone transactions cache a server timeout below the remaining request budget and refresh it as the budget shrinks; joined cell transactions keep per-statement settings because policy SQL shares their client. These local timings and round-trip counts are comparative observations, not Railway or Hyperdrive latency claims.

Migration 030 adds the batch ledger and eight write slots to the shared database, including backfill for existing collections; no per-collection table is created. Migration 031 adds the missing-value index and a deferred completeness check. The migrator locks declaration rows before records and index DDL, matching backfill order, and refuses a populated `records` table unless `STATEPLANE_POPULATED_INDEX_UPGRADE=drained` is set after stopping record writers and backfill workers. Its preflight takes a writer-excluding records lock without waiting behind an active writer, then holds the locks through commit. A ready declaration with an existing projection gap becomes pending rather than misclassifying a present value as missing. All pending backfill cursors restart from the beginning; run `backfill` until each intended field is ready before restoring `queryPage`, `queryRecords`, `countRecords`, and `existsRecord` requests that use that field in a filter or sort. Exact ID/key lookups and unfiltered counts remain available. During a rolling writer cutover, a pre-031 writer that omits a declared projection is rejected at commit, so retry its unchanged idempotency request through the upgraded writer. Stop writers while applying the migration and keep old writers out of service after the cutover; the deferred check protects against stragglers, but this is not a substitute for a drained migration. The cell operational role needs `SELECT, INSERT, UPDATE` on `collection_write_slots` and `SELECT, INSERT, UPDATE` on `batch_operations` and `batch_items`, plus the existing collection/record grants and `SELECT` on index declarations and projections for the deferred check. Do not grant batch table access to the disposable qualification role. Verify these privileges through the intended operational role after migration and restore. Space erasure removes the batch ledger and cascades slot rows when collections are deleted. The restore smoke includes populated batch state and slots in its archive comparison.

Migration 032 stages the nonnegative batch-attempt guard without scanning historical items under its DDL lock. The migrator commits 032, then migration 033 validates historical rows under a lock that permits concurrent batch writes. If an old negative attempt makes validation fail, 032 remains committed and rejects new negative writes; repair the affected row and rerun the migrator to complete 033. The local PostgreSQL 16 upgrade test uses 2,000 records, an invalid historical batch item and an active writer: it observes 031 drain refusal, then the committed 032 prefix, failed 033, corrected-item replay and validated constraint. A separate lock test observes 033 waiting while a batch update succeeds under a 1,500 ms statement timeout. On a populated local test database with 10,283 live rows, 25,281 projection rows and 108 declarations, `EXPLAIN (ANALYZE, BUFFERS)` of 031's correlated completeness predicate produced a hash anti join, 914 shared-hit blocks and 13.2 ms execution. The correlated `NOT EXISTS` checks preserve gap detection; this plan did not execute one nested scan per declaration. These tests establish local lock and plan behavior; Railway lock duration remains to be measured.

External acceptance for this issue requires an exact-head disposable Railway Postgres migration and operational-role read/write/plan probe, including interruption and replay over its real endpoint; Cloudflare Preview with Hyperdrive must exercise the serialized page and batch boundaries with private cursor key and time/backpressure errors. A connected provider sandbox is relevant only to verify that Stateplane does not ingest third-party credentials or scrape on its own; no provider effect is part of these SQL APIs. Aside Browser can observe a later authenticated transport/UI journey, but STA-9/10 own those public surfaces. Record unavailable boundaries as unverified and use the final STA-21 regional qualification for integrated live routing and browser evidence.
