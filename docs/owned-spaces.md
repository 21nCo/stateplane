# Owned spaces and regional authority (STA-6)

## Contract and owners

An AuthFn session can create, list, inspect, update, archive, restore, suspend and delete its own personal spaces. A session may choose only a cell in the server's configured cell map; omission uses the configured default. API keys cannot create spaces or change their lifecycle. A key with `space:admin` on a current collection may inspect only that space's directory metadata: space ID, owner principal ID, home cell ID, storage target ID, lifecycle, policy version, placement generation and timestamps; it gains no content read. AuthFn verifies session, OAuth-backed session, cookie session or API-key identity. Stateplane maps each issued key ID to a distinct agent principal in exactly one cell, stores collection grants there, and makes every policy decision. The bearer secret is returned once and is never stored in Stateplane SQL or audit rows.

`PostgresSpaces` owns the control directory and lifecycle operations. The control database contains placement and owner metadata, not collection grants. The router checks owner or current collection grant before returning placement, and conceals other owners' space IDs. `PostgresCellPolicy` owns cell authorization; it checks the key mapping, grant, expiry, lifecycle, policy version and placement generation from the selected cell database, and re-reads the AuthFn credential by ID at admission and before commit. A provider lookup failure denies the effect. The callback receives a scope-bound record transaction, not a raw pooled client. Source, claim, blob and provider adapters added by their later tickets must run their effects inside the same guarded callback and use its space/collection scope; they must call `authorizeEffect()` immediately before each external effect to recheck current provider status. Public HTTP, MCP and CLI transports belong to STA-9/10; their current cell Worker scaffold still returns 503 and must use this boundary before enabling routes.

The router treats a requested space ID only as a directory selector. It issues an HMAC-SHA256 assertion bound to `stateplane-cell:<cellId>`, space, collection, capability, credential ID, current policy version, placement generation, issue/expiry times and random nonce. The destination verifies the signature and audience before SQL, then consumes the nonce in a committed statement separate from the effect transaction. A callback rollback does not restore replay authority. Expiry is rechecked against the database clock after pool acquisition, at each record or external effect boundary, and before commit; the Worker clock provides an additional early rejection. A direct cell call with a bearer credential, a wrong-cell assertion, an expired assertion or a second use cannot enter an effect callback. Rotation signs with one active key ID and verifies retained keys until their retirement. Signing secrets must be distinct from AuthFn secrets and supplied as private environment bindings. Never log assertions, bearer credentials or secrets.

The router currently issues a 30-second assertion, and verification refuses any lifetime over 60 seconds or issue time more than five seconds ahead of the cell clock. A signing key must contain at least 32 bytes. These are initial security bounds for one gateway-to-cell hop, not measured Cloudflare latency or provider limits. Verify Preview clock behavior and p99 hop time before changing them. AuthFn sessions/keys have their own provider expiry. Cell SQL checks key and grant expiry against the database clock both before and after the effect.

## State, races and recovery

`active` allows granted reads and writes. `readOnly` allows granted reads and repository receipt replay under the current write grant; the repository rejects fresh record writes. `suspended` and `deleting` deny content effects. `deleted` is hidden from ordinary listing/routing. Deletion requires an archived or suspended space. It changes the cell and directory to `deleting`, revokes every AuthFn key whose provider acknowledgement is still pending, purges collection content in a scoped transaction and publishes `deleted` only after the cell has no content or keys. The immutable space audit and a deleted space tombstone remain. Local denial and provider acknowledgement are separate audited steps; a failed provider call can be retried through revoke, rotate or delete. If provider revocation or purge fails, `deleting` remains denied and the owner may retry deletion. An inconsistent restore may leave a cell marked `deleted` with retained data. Delete and reconcile reject that state before directory publication. The current owner can call `repairDeletedErasure` while the directory is `deleting` or `deleted`; it settles key revocation, transactionally re-enters `deleting` only inside the cell transaction, purges, verifies erasure, and writes one repair audit event. The owner then retries delete to publish the tombstone. A failed control publication leaves the cell version ahead, so old assertions fail closed; `reconcile` repairs an interrupted publication after comparing owner, cell and storage target, using a directory version/fence compare-and-swap that refuses to overwrite a newer publication. `fencePlacement` increments the generation in the cell before publishing it in the directory. It does not move data; a move needs a separately verified copy/cutover procedure.

Creation first reserves an unrouteable `provisioning` directory row with a 60-second database-clock claim. The creator then locks that row in an explicit transaction through the cell commit. Owner listing skips a claimed row. Once the claim expires, recovery locks it and publishes a matching committed cell with its creation audit, or retires an absent cell and records an immutable control-side `space:provision-retired` event. A creator that loses the row lock to recovery fails before cell effects. The deleted directory tombstone and retirement event survive retries; an incomplete or mismatched cell fails closed. The 60-second bound is a recovery deadline, not a measured provider limit; the row lock protects longer live cell commits. This also works with a one-connection shared pool because the cell insert uses the control transaction.

The cell holds shared policy, credential and grant locks through its effect and commit. A local revocation obtains the cell's write lock first, removes grants and bumps policy there, then publishes the control version and revokes the AuthFn primitive. An in-flight effect that acquired its lock first may finish; revocation waits for it. Every later effect fails at the cell, including an assertion issued before revocation. If the control directory is unavailable or stale, requests fail rather than using a cached global grant. A failed commit has unknown outcome and must be retried with the original operation's idempotency key. Provider/blob effects must be idempotent or staged through an outbox; the guard establishes authorization, not distributed commit of an external side effect.

Owner audit reads return `{entries,nextCursor}` in `(recorded_at,audit_id)` order. Each call reads at most 101 rows and returns at most 100; a cursor is scoped to its space and continues after the last returned row. This fixed initial page bound limits memory per request and is not a measured transport throughput limit. An invalid or cross-space cursor fails before the audit query. Only a current owner session can read the audit, including while the space is archived.

Joined record receipts become readable only after the enclosing cell transaction commits. Each receipt keeps its creating authority's retention; the cell rechecks every joined scope and original replay grant after finalization. A receipt that expires before commit rolls the transaction back with `RECEIPT_EXPIRED`, distinct from `RECEIPT_PENDING` while a receipt is still uncommitted or reserved.

Agent key issuance validates every collection before creating a provider key. A second collection check runs under row locks after creation to catch concurrent deletion. A control-plane issuance journal commits before AuthFn creation, and the AuthFn key carries its journal correlation ID in provider metadata. A database-clock, 60-second per-space control claim excludes routine reconciliation during a live issuance without pinning a connection through AuthFn I/O. Every later staging, grant, activation and confirmation boundary rechecks the claim and cancellation journal; expiry fails closed and compensates a late provider result. After cell confirmation, the issuer durably marks its journal complete under the live claim before returning a definite success. Routine reconciliation atomically cancels only an incomplete journal under its own live claim before provider revocation. A stale reconciler cannot revoke a successor's key after its claim expires, and cancellation prevents a delayed issuer from completing. Existing journal rows retain their cell-confirmation readback behavior during upgrade. Routine reconciliation can claim an expired issuer and retry correlation lookup/revocation. Deletion cancels the journal without waiting for a paused provider call, and cannot publish `deleted` until its outcome is settled. This permits provider lookup and revocation even when cell staging fails, deletion races creation, or the generated key ID cannot be recorded after a lost acknowledgement. A rejected create records its failure in the journal; only a successful correlation lookup proving no key settles it without revocation. A lost acknowledgement that did create a key retains its ID for revocation. `reconcile` and deletion process unresolved journal entries; an unavailable provider or an interrupted create with no definitive outcome leaves them pending and blocks completed deletion. The 60-second lease is an initial fail-closed coordination deadline, not measured AuthFn latency; connected sandbox evidence must check that normal provider calls finish within it. The unconfirmed cell credential and a `key:created-pending` audit event commit separately before grants. Invalid collection input returns `INVALID_ARGUMENT` without creating a key; rotation checks it before revoking the old key. Grant snapshots use own array slots so inherited numeric accessors cannot alter SQL grants or audit details. The journal stores key IDs and status, never bearer secrets.

If the completion write, readback, and retry are all unavailable after cell confirmation, issuance rejects with `AgentKeyOutcomeUnknownError`. The explicit, single-use `takeKey()` method returns the bearer for recovery; ordinary error formatting does not contain the secret. Callers must treat that bearer as uncertain and never log it. A completed journal retains that key across reconciliation. After the claim expires, reconciliation can cancel an incomplete journal and attempt provider revocation; an outage can leave the key active until recovery succeeds. This applies to issue and rotation, where the old key may already be revoked. Ordinary `IssuedAgentKey` success is returned only after durable journal completion is observed.

Migration 016 backfills the directory from existing spaces when the control and cell tables share a database. For separate databases, drain owner writes and routing, migrate control and every cell, then run `pnpm db:backfill-directory` with `STATEPLANE_CONTROL_URL`, `STATEPLANE_CELL_URLS` (a JSON array of `{cellId,url}` for every configured cell), `STATEPLANE_TOPOLOGY_ENV=development` or `production`, and `STATEPLANE_BACKFILL_DIRECTORY_DRAINED=1`. The flag is an explicit operator assertion that traffic is stopped. The command checks the selected topology’s complete cell set, locks every source table before reading, copies precise timestamps, and reports copied versus already present rows. A lock timeout or mismatch aborts publication. Compare owner list/get and directory lookup before resuming traffic; do not invent a placement from an untrusted request.

Migration 025 adds the stable home cell to the control directory. A shared database copies it from `spaces` during migration. An existing separate control database retains null home cells until the drained backfill copies and verifies each cell's value. Run that backfill before restoring traffic; owner and agent metadata reads fail closed while a home cell is unknown. The backfill rejects a non-null conflict rather than replacing a previously published home cell. Current placement and its generation continue to fence routing independently of the stable home cell.

After migration and after restore, run `pnpm db:grant-control-journal` through the direct administrative control connection with `STATEPLANE_CONTROL_URL` and the protected inventory’s `STATEPLANE_CONTROL_ROLE`. It grants that role only SELECT, INSERT and UPDATE on `agent_key_issuances` and reads privileges back. Verify a real issuance and reconciliation through that operational role before routing traffic. Do not grant the journal to a disposable probe or regional cell role.

Migration 012's scoped purge routine is `SECURITY DEFINER`, revokes default `PUBLIC` execution, requires `deleting`, and is the sole deletion path through immutable record-event and collection-version triggers. Provisioning must explicitly grant `EXECUTE ON FUNCTION public.stateplane_purge_space(text)` to the cell's operational role only, after the repository's role-admission checks. Do not grant it to a settings, disposable probe or control role. The routine retains audit metadata but erases records, versions, grants, receipts, outbox, entity references and nonces. Future child tables must join that purge transaction before their features can ship.

Rotation consumes an active source key once. If validation fails before revocation, the owner may retry the same source. Once local revocation commits, a repeated or concurrent rotation with that source fails with `STALE_PLACEMENT` before AuthFn creates another key, even if provider revocation or replacement issuance failed. The owner can retry provider cleanup with `revokeAgentKey` and issue a new key explicitly. Reconciliation treats a journaled provider revocation as terminal and repairs any remaining local credential and grants before publishing the cell version; a failed cell compensation write remains retryable without another provider revoke.

## Focused risk matrix

| Surface | Failure to prevent | Evidence |
| --- | --- | --- |
| Identity and grants | Key inherits its owner's authority; record reader/writer becomes schema or export admin | AuthFn bearer/cookie/CSRF qualification; two-agent, two-collection SQL denial matrix |
| Routing | Selector, direct cell call, tampering, rollback replay or wrong audience produces an effect | Signature, durable one-use nonce, wrong-cell, cross-owner and missing-token integration cases |
| Freshness | Provider-revoked credential, expired assertion or stale placement passes from a pooled connection | AuthFn readback, cell SQL checks, pool-wait expiry, rotation, placement fence and revocation-race cases |
| Lifecycle | Interrupted provision/delete or inconsistent restore leaves usable content or publishes an unpurged tombstone | Provisioning is unrouteable; `deleting` denies effects; deleted-cell repair, erasure proof, retry and immutable-audit SQL readback |
| Operations | A failed remote/provider call or process stop loses the control/cell version sync | Durable pending provider acknowledgement, cell-first publication, reconcile CAS and ambiguous-BEGIN client discard; exact-head Railway/Preview checks remain required |
| Runtime coordination | Hyperdrive transaction pooling drops session locks; one-connection pool stalls while provider create is paused; an expired reconciler revokes a successor's key | Database-clock claims, explicit row locks, journal completion/cancellation barriers for issue and rotation in separate and one-connection pools, paused-provider archive/delete and interrupted-issuer recovery; exact-head Hyperdrive readback remains required |
| Rotation and cleanup | A reused source issues two replacements; provider revoke succeeds but failed cell compensation strands grants | Concurrent and response-retry rotation, failed preflight retry, issue/rotation compensation outage and reconciliation journal/cell/audit readback |
| Upgrade | Existing cell spaces disappear from the new control directory | Single-database migration backfill and drained cross-database copy with owner list/get and route readback |
| Audit | Retained history grows beyond one response or a cursor crosses spaces | Fixed 100-row keyset pages, tie ordering, malformed/cross-space cursor and owner denial cases |

The local integration suite can use `STATEPLANE_TEST_SEPARATE_DBS=1` with a disposable PostgreSQL admin URL to create three temporary databases, migrate each one, prove control/cell row isolation and remove all three. Without that flag it runs the same policy checks in one disposable database. `pnpm test:postgres` includes the suite. Neither mode proves Railway TLS, Hyperdrive, Cloudflare service bindings or a connected OAuth/provider sandbox. Those need exact-head acceptance through the configured Composio → Railway → Cloudflare Preview → Aside Browser sequence. In particular, verify AuthFn session/OAuth and key revocation against a connected sandbox, one service per control/cell database with a real cross-cell denial, a routed repository and blob/provider denial before effects, the deployed direct-cell response, Preview cleanup, and an owner/agent browser journey. Keep the card held if any of those required boundaries cannot be observed.
