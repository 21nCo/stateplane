# Owned spaces and regional authority (STA-6)

## Contract and owners

An AuthFn session can create, list, inspect, update, archive, restore, suspend and delete its own personal spaces. A session may choose only a cell in the server's configured cell map; omission uses the configured default. API keys cannot create spaces or change their lifecycle. A key with `space:admin` on a current collection may inspect only that space's lifecycle metadata; it gains no content read. AuthFn verifies session, OAuth-backed session, cookie session or API-key identity. Stateplane maps each issued key ID to a distinct agent principal in exactly one cell, stores collection grants there, and makes every policy decision. The bearer secret is returned once and is never stored in Stateplane SQL or audit rows.

`PostgresSpaces` owns the control directory and lifecycle operations. The control database contains placement and owner metadata, not collection grants. The router checks owner or current collection grant before returning placement, and conceals other owners' space IDs. `PostgresCellPolicy` owns cell authorization; it checks the key mapping, grant, expiry, lifecycle, policy version and placement generation from the selected cell database, and re-reads the AuthFn credential by ID at admission and before commit. A provider lookup failure denies the effect. The callback receives a scope-bound record transaction, not a raw pooled client. Source, claim, blob and provider adapters added by their later tickets must run their effects inside the same guarded callback and use its space/collection scope; they must call `authorizeEffect()` immediately before each external effect to recheck current provider status. Public HTTP, MCP and CLI transports belong to STA-9/10; their current cell Worker scaffold still returns 503 and must use this boundary before enabling routes.

The router treats a requested space ID only as a directory selector. It issues an HMAC-SHA256 assertion bound to `stateplane-cell:<cellId>`, space, collection, capability, credential ID, current policy version, placement generation, issue/expiry times and random nonce. The destination verifies the signature and audience before SQL, then consumes the nonce in a committed statement separate from the effect transaction. A callback rollback does not restore replay authority. Expiry is rechecked after pool waits and before the effect. A direct cell call with a bearer credential, a wrong-cell assertion, an expired assertion or a second use cannot enter an effect callback. Rotation signs with one active key ID and verifies retained keys until their retirement. Signing secrets must be distinct from AuthFn secrets and supplied as private environment bindings. Never log assertions, bearer credentials or secrets.

The router currently issues a 30-second assertion, and verification refuses any lifetime over 60 seconds or future issue time. A signing key must contain at least 32 bytes. These are initial security bounds for one gateway-to-cell hop, not measured Cloudflare latency or provider limits. Verify Preview clock behavior and p99 hop time before changing them. AuthFn sessions/keys have their own provider expiry. Cell SQL checks key and grant expiry against the database clock both before and after the effect.

## State, races and recovery

`active` allows granted reads and writes. `readOnly` allows granted reads and repository receipt replay under the current write grant; the repository rejects fresh record writes. `suspended` and `deleting` deny content effects. `deleted` is hidden from ordinary listing/routing. Deletion requires an archived or suspended space. It changes the cell and directory to `deleting`, revokes every AuthFn key whose provider acknowledgement is still pending, purges collection content in a scoped transaction and publishes `deleted`. The immutable space audit and a deleted space tombstone remain. Local denial and provider acknowledgement are separate audited steps; a failed provider call can be retried through revoke, rotate or delete. If provider revocation or purge fails, `deleting` remains denied and the owner may retry deletion. A failed control publication leaves the cell version ahead, so old assertions fail closed; `reconcile` repairs an interrupted publication after comparing owner, cell and storage target, using a directory version/fence compare-and-swap that refuses to overwrite a newer publication. `fencePlacement` increments the generation in the cell before publishing it in the directory. It does not move data; a move needs a separately verified copy/cutover procedure.

The cell holds shared policy, credential and grant locks through its effect and commit. A local revocation obtains the cell's write lock first, removes grants and bumps policy there, then publishes the control version and revokes the AuthFn primitive. An in-flight effect that acquired its lock first may finish; revocation waits for it. Every later effect fails at the cell, including an assertion issued before revocation. If the control directory is unavailable or stale, requests fail rather than using a cached global grant. A failed commit has unknown outcome and must be retried with the original operation's idempotency key. Provider/blob effects must be idempotent or staged through an outbox; the guard establishes authorization, not distributed commit of an external side effect.

Agent key issuance validates every collection before creating a provider key. A second collection check runs under row locks after creation to catch concurrent deletion. A control-plane issuance journal commits before AuthFn creation, and the AuthFn key carries its journal correlation ID in provider metadata. This permits provider lookup and revocation even when cell staging fails, deletion races creation, or the generated key ID cannot be recorded after a lost acknowledgement. `reconcile` and deletion process unresolved journal entries; an unavailable provider leaves them pending and blocks completed deletion. The unconfirmed cell credential and a `key:created-pending` audit event commit separately before grants. Invalid collection input returns `INVALID_ARGUMENT` without creating a key; rotation checks it before revoking the old key. Grant snapshots use own array slots so inherited numeric accessors cannot alter SQL grants or audit details. The journal stores key IDs and status, never bearer secrets.

Migration 016 backfills the directory from existing spaces when the control and cell tables share a database. For separate databases, drain owner writes and routing, migrate control and every cell, then run `pnpm db:backfill-directory` with `STATEPLANE_CONTROL_URL` and `STATEPLANE_CELL_URLS` (a JSON array of `{cellId,url}` for every configured cell). The command rejects duplicate cells and mismatched existing placements and can be retried. Verify every cell was supplied and compare owner list/get and directory lookup before resuming traffic. An omitted cell remains unrouteable until copied; do not invent a placement from an untrusted request.

Migration 012's scoped purge routine is `SECURITY DEFINER`, revokes default `PUBLIC` execution, requires `deleting`, and is the sole deletion path through immutable record-event and collection-version triggers. Provisioning must explicitly grant `EXECUTE ON FUNCTION public.stateplane_purge_space(text)` to the cell's operational role only, after the repository's role-admission checks. Do not grant it to a settings, disposable probe or control role. The routine retains audit metadata but erases records, versions, grants, receipts, outbox, entity references and nonces. Future child tables must join that purge transaction before their features can ship.

## Focused risk matrix

| Surface | Failure to prevent | Evidence |
| --- | --- | --- |
| Identity and grants | Key inherits its owner's authority; record reader/writer becomes schema or export admin | AuthFn bearer/cookie/CSRF qualification; two-agent, two-collection SQL denial matrix |
| Routing | Selector, direct cell call, tampering, rollback replay or wrong audience produces an effect | Signature, durable one-use nonce, wrong-cell, cross-owner and missing-token integration cases |
| Freshness | Provider-revoked credential, expired assertion or stale placement passes from a pooled connection | AuthFn readback, cell SQL checks, pool-wait expiry, rotation, placement fence and revocation-race cases |
| Lifecycle | Interrupted provision/delete leaves usable content or a partial purge | Provisioning is unrouteable; `deleting` denies effects and retries; erasure and immutable-audit SQL readback |
| Operations | A failed remote/provider call or process stop loses the control/cell version sync | Durable pending provider acknowledgement, cell-first publication, reconcile CAS and ambiguous-BEGIN client discard; exact-head Railway/Preview checks remain required |
| Upgrade | Existing cell spaces disappear from the new control directory | Single-database migration backfill and drained cross-database copy with owner list/get and route readback |

The local integration suite can use `STATEPLANE_TEST_SEPARATE_DBS=1` with a disposable PostgreSQL admin URL to create three temporary databases, migrate each one, prove control/cell row isolation and remove all three. Without that flag it runs the same policy checks in one disposable database. `pnpm test:postgres` includes the suite. Neither mode proves Railway TLS, Hyperdrive, Cloudflare service bindings or a connected OAuth/provider sandbox. Those need exact-head acceptance through the configured Composio → Railway → Cloudflare Preview → Aside Browser sequence. In particular, verify AuthFn session/OAuth and key revocation against a connected sandbox, one service per control/cell database with a real cross-cell denial, a routed repository and blob/provider denial before effects, the deployed direct-cell response, Preview cleanup, and an owner/agent browser journey. Keep the card held if any of those required boundaries cannot be observed.
