# Owner UI (STA-11)

The SvelteKit app manages spaces, collections, records, agent access, audit and ingestion. Pages render on the server. Every load and form action calls `api()` in `app/src/lib/server/api.ts`. That function builds a standard `/v1` request and passes it to the same HTTP handler, identity verifier and services used by the CLI and MCP. The UI has no write path or authorization logic of its own. A browser can only send a form; the API decides each result.

## Sessions

Sign in with a session bearer or an agent key. The app checks it with `GET /v1/auth/session`. It then stores the bearer in an HttpOnly, `SameSite=Strict` cookie, which is `Secure` over HTTPS and lasts eight hours. Each page sends that bearer to the API again, so a revoked or expired credential stops working on the next request. SvelteKit rejects cross-origin form posts. The CSP keeps scripts, forms and framing on this origin. Pages send `no-store` and `no-referrer`, because page cursors appear in URLs. An agent key cannot list spaces or read placement unless it holds `space:admin`. It sees only its granted collections, and denied actions show the API's error code.

## Behavior

- **Spaces.** Create a space with a server-generated `sp_` ID. Resubmitting after `COMMIT_OUTCOME_UNKNOWN` reuses that ID. The optional home cell is passed to the API, which accepts only its configured cells. The overview shows lifecycle, home and current cell, storage target, placement generation and policy version. The switcher lists the first page of spaces and always selects the open space; the space list pages through the rest.
- **Routing.** Page URLs encode each identifier as the API does: `.` and `..` become `;.` and `;..`, and pages read identifiers from the raw path. SvelteKit strips a trailing `__data.json` or `__route.js` from a path, so a name ending in either has its first `_` escaped as `%5F`. Collections are defined at `/spaces/{space}/new-collection`, so a collection named `new` keeps its own URL. Forms send space, cell and collection IDs, external keys and operation keys exactly as entered. A value is absent only when empty; any other value, whitespace included, goes to the API, which alone normalizes and validates it. A name with surrounding whitespace is shown quoted, with invisible characters escaped, so ` items ` and `items` stay distinguishable.
- **Schemas.** Owners define and revise a collection from JSON. A revision sends the loaded version in `If-Match`, so a concurrent revision returns `SCHEMA_CONFLICT` instead of replacing the other edit. Define and revise have no request key. After an uncertain define the form asks the owner to check whether the collection exists; a define whose name is taken marks the name field and links to that collection. After `COMMIT_OUTCOME_UNKNOWN` the form asks the owner to load and compare the current definition, and never reports a later conflict as an unapplied edit. New filter and sort fields stay pending until the owner builds them with `POST …/indexes/{field}`. Each call commits at most 100 records. One click makes at most 20 calls (2,000 records) to keep a request bounded; click again to continue.
- **Records.** Filters take their type from the field's schema (string, number, boolean or UTC date-time). Invalid values are flagged on the field before any query is sent: numbers use JSON decimal syntax only, and instants must be real calendar dates and clock times (23:59:60 is left to the API). Sorting uses only ready sortable fields. The page size is 1–100, defaulting to 25, and pagination follows the API's forward cursor. Each create and edit carries an idempotency key generated when the form loads. After an uncertain commit, resubmitting the unchanged form recovers the original receipt. The generic `COMMIT_OUTCOME_UNKNOWN` text never promises recovery; only forms that send a retry identity say to submit again.
- **Conflicts.** Edits and deletes send the revision the user loaded. On `REVISION_CONFLICT`, the page shows the user's draft next to the current revision; nothing is overwritten. The user can keep the current record, or explicitly apply the draft as a new write against the current revision. Apply sends the editor's text, including any merge the user makes there. `NOT_FOUND` on a write to a loaded record is a concurrent delete: the draft stays visible, and deletion is claimed only when a reread also returns `NOT_FOUND`. Any other reread failure is shown as an error, with no apply action. Drafts, errors and retries render even when the record can no longer be read. After an uncertain delete, the retry reuses the original request key and revision.
- **Revisions and projections.** Record pages show the revision, schema version and search projection state. A pending projection means search may lag behind; exact reads are current. The Changes page lists committed events.
- **Agent access.** Issuance offers 1, 7, 30 or 90 day lifetimes; these are UI presets, not service limits. The owner chooses capabilities per collection. The secret appears only in the issuance response, and the key list returns IDs, status and grants. Issuance has no request key, so after `COMMIT_OUTCOME_UNKNOWN` the owner is told to check the key list rather than to retry. Revocation removes grants and denies the key at once, then revokes it at the provider. Until the provider step completes, the key shows provider cleanup pending, with a retry. A key is active only after its issuance is activated and confirmed; until then it shows pending. "Check a key" reports two results for a pasted secret. The first is provider authentication (`GET /v1/auth/session`). The second is this space's authorization, checked by collection discovery, which needs a read, write or schema grant. A key revoked here is denied by the space even while the provider still accepts it. Only `UNAUTHENTICATED` reads as a provider rejection; other failures, and a secret with characters no header can carry (which is never sent), do not confirm revocation. If collection discovery fails, the grant form reports the error instead of an empty or truncated list. The audit shows creation, lifecycle, issuance and revocation events; a rejected audit cursor (`CURSOR_INVALID`) offers the first page.
- **Ingestion.** Submits 1–20 NDJSON lines under an operation key and shows each item's progress. It can retry failed items or cancel pending ones.

Styling follows the Skillplane token convention: `app/src/app.css` is the only file with raw colors, and components use semantic Tailwind roles, visible focus and a reduced-motion fallback. Wide tables scroll inside labelled regions that keyboard users can focus.

## Fixture host and tests

The opt-in local host (see [HTTP and CLI](http-cli.md)) adds Node-only, in-memory agent keys so local journeys can issue, use and revoke a key. It holds at most 1,000 keys. They survive a retired connection pool but are lost when the process restarts. A Worker host builds a fresh host and pool per SvelteKit request, shared by every API call in that page render and retired after the response, and keeps issuance disabled. Key issuance on Preview therefore needs connected AuthFn, which is checked by the STA-21 acceptance gate.

`pnpm test:e2e` starts the UI. If `DATABASE_URL` or the local Compose password is available, it first creates and migrates a disposable database, and drops it on exit or failed startup. The UI reaches it through a loopback proxy. Local tests use the proxy's control port, 5744, to drop one database reply, which reproduces a lost commit acknowledgement. The same port can fail the fixture provider's next revocation (`STATEPLANE_TEST_PROVIDER_FAULT_URL`, honored only when `STATEPLANE_ENV=local`). The launcher drops the database however the UI process ends; a second signal during cleanup exits at once. The suite runs the owner journey, the conflict flow, validation and region denial. It issues, uses and revokes a key, runs ingestion, and checks every page with axe (WCAG 2.2 AA tags) at 390 px and 1440 px, plus keyboard sign-in. To run the same journeys against a deployed development service, set `STATEPLANE_E2E_BASE_URL` and `STATEPLANE_E2E_TOKEN`. The key journey needs a host that can issue keys.

Local runs do not prove Railway Postgres, Cloudflare Preview with Hyperdrive, connected AuthFn sessions and key revocation, or Aside Browser observation. Those remain exact-head external acceptance boundaries.
