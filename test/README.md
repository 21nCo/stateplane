# Executable v1 contract fixtures

Run `npm test` (Node 20+, no package install required). `test/contract.test.js` exercises generic `entries` with synthetic values against `test/reference.js`. The reference is a deterministic synchronous contract oracle, **not** a SQL adapter, API server, secure production cursor implementation or evidence of deployed regional infrastructure. Its synthetic receipt timestamps/expiry are placeholders; retention is not chosen. It intentionally models only the tested subset (records, grants, compatible schema additions, simple keyset pages and projection rebuild); sources, claims, links, snapshots, real concurrency, indexed query plans and routing need downstream fixtures against real adapters. Do not ship this oracle as service code.

Explicit oracle limits: `define`/`revise` are uncredentialed setup helpers, so the suite does **not** prove `schema:write` authorization, lifecycle fencing or commit-time policy checks for schema operations (STA-7, with STA-6 for auth). Receipts are committed synchronously: an in-flight reservation and `RECEIPT_PENDING` for a concurrent matching retry are **not modeled**; STA-5 owns transaction/serialization adapter fixtures (including a delayed first commit and same-key retry), not the sequential replay tests here. `revise` changes only the JSON Schema: unique/filterable/sortable index-declaration evolution, typed-index backfill and ready-flag checks are **not modeled**. STA-7 owns version-checked declaration changes, backfill/readiness and their adapter fixtures; STA-8 owns before/after readiness query fixtures. The reference collection definition also has no collection enum-transition lifecycle rule: create/replace/patch transition checks, rule-change breaking revisions and concurrent commit enforcement are **normative but untested here**. STA-7 owns a rule-aware adapter and fixtures for permitted/forbidden transitions and rule revisions; the space-level `lifecycle` helper tests only space read/write availability, not collection transitions. There is no link/source/claim oracle: STA-13 owns adapter fixtures for restrict/detach on either endpoint (including mixed policies, races and no live dangling link). The oracle accepts only unfiltered queries/counts/exists; any supplied filter fails `INVALID_ARGUMENT` instead of silently returning unfiltered results. Typed filters and filter-bound cursor digests require an adapter and fixtures from STA-8. The signed cursor models credential/space/collection/policy/schema and selected sort/position only; it does **not** model placement generation, actual expiry, secret rotation or multi-cell routing (STA-8 cursor/query adapter, with STA-6 placement/auth). Real adapters must add fixtures for these omissions; none relax the normative v1 contract.

Coverage: space isolation/revocation and independent per-collection grants (no wildcard), create-only/NFC/fixed-White_Space external keys and generated-ID namespace separation, collision-safe composite reservations with distinct per-collection constraint names and replacement release, typed declared scalar unique/sort path validation without numeric coercion, null/missing and nullable enum checks, Unicode scalar validity for external keys and composite string data, valid UTC instant parsing/canonical uniqueness, immutable key input rejection, failure atomicity including event/receipt/outbox and invalid operation-specific payload fields, mandatory revision with competing writers, declared-optional-only unset and valid absent-field no-op patches, lost committed response and old-revision replay across compatible schema additions with caller-supplied schema precondition, current write-grant requirement for replay despite read-only grant changes and space `readOnly` lifecycle, original-collection reauthorization before mismatch disclosure and UTF-8 ordered fingerprint keys, changed-payload rejection, tombstone key reservations, cursor scope/policy binding and malformed-supplied-cursor rejection, creation-order keyset resume across ID width boundaries and optional scalar sort pages with missing/null/value partition and ID tie-breaking in both directions, unfiltered authoritative count/exists and fail-closed filtered calls, projection rebuild with exact-state preservation, closed-object and malformed-keyword schema rejection at every depth, codepoint string length, literal `description` field compatibility, top-level-only optional additions, immutable accepted definitions and space lifecycle rejection. The oracle uses synthetic monotonic creation timestamps only to model default `(createdAt,id)` ordering; it does not test real clock behavior. `ARCHITECTURE.md` and `contracts/v1.md` define the wider normative contract.

Additional coverage: the `integer` subset accepts both safe binary64 endpoints and rejects values just beyond them (including enum definitions), while finite `number` stays distinct. The mode-specified key lookup fixture checks colliding generated-ID/external-key text, external normalization, no cross-mode or cross-space fallback, authorization-before-key parsing, and tombstone invisibility; STA-7/8 must repeat these against the real mutation/query adapter.

Hosted-review regressions: the reference grants only the normative `records:read` and `records:write` capability tokens; unknown tokens fail at grant time before changing policy. Count/exists reject supplied page cursors rather than returning partial results. Failed mutation fixtures compare complete records, reservations, events, outbox and receipts, and reattempt a conflicting reservation; default pages force equal timestamps across the `rec_9`/`rec_10` ID boundary. Composite string uniqueness normalizes reservation values to NFC while preserving stored spelling. Optional prototype-named fields use own-property presence, non-JSON root/nested object instances fail closed, and long key/date-time inputs exercise linear-time normalization. Data/set JSON compatibility and patch shape are checked before fingerprint/replay, while current schema/revision validation follows authorized committed replay; fixtures cover invalid array/object aliases, custom-prototype arrays, explicitly present undefined non-applicable fields across operations, fresh rejection, unchanged effects and revoked grants. Nested rejection fixtures snapshot both affected collections' rows and reservations. Reordered required/enum/nullable type members remain schema-compatible, while sparse keyword arrays and duplicate scalar/structural enum members fail `SCHEMA_UNSUPPORTED` before define/revise effects. Collection unique/sort declaration arrays also reject sparse/decorated shapes; optional schema keyword presence with `undefined` rejects without effects. An IERS-announced leap second is accepted for records, canonical reservations and chronological sorts, while unannounced `:60` remains invalid. Supplied noncanonical base64url and JSON envelope cursor aliases fail `CURSOR_INVALID` even when they decode to a correctly signed binding; valid continuation and auth-before-decoding remain tested. The suite remains an in-memory oracle, not a provider performance or concurrency qualification.

Hosted round 8 adds lifecycle-order and ID-shape fixtures: receipt-less malformed create/patch requests in a `readOnly` space fail `SPACE_UNAVAILABLE` before payload checks; committed retries validate their payload before matching the saved receipt, and current write-grant revocation denies both. Existing-record replace/patch/delete reject missing, non-string, empty and malformed-Unicode IDs before receipt lookup, while a valid unknown ID remains `NOT_FOUND`. Complete row/reservation/event/outbox/receipt snapshots prove effect-free failures; the oracle still cannot model concurrent receipt reservations or policy races.

Hosted round 11 checks authorization of hidden own mutation targets before envelope-shape rejection: authorized callers get `INVALID_ARGUMENT`, revoked callers get `FORBIDDEN`, and rejected writes leave rows, reservations, events, outbox and receipts untouched. Under isolated and restored `Object.prototype` pollution, schemas missing their own root `$schema`, child `type`, or root/nested `additionalProperties:false` fail `SCHEMA_UNSUPPORTED` at definition and revision without changing collection state. Valid own-keyword definitions, optional additions and record writes remain usable despite inherited optional keywords. These are reference-oracle regressions, not real transport or database race proofs.

Hosted round 12 checks that transparent in-process proxies of root/nested schemas, definition arrays/descriptors and record data are rejected with stable errors before clone, fingerprint or receipt replay; rejected calls leave rows, reservations, events, outbox, receipts and definition versions unchanged. `minLength`/`maxLength` and `minItems`/`maxItems` accept nonnegative integer bounds beyond the record `integer` safe range at definition and compatible revision, while malformed values fail closed. These are Node in-memory oracle fixtures, not a configured resource-budget or adapter proof.

For a real repository conformance suite, preserve test names and expected outcomes while replacing the oracle with an adapter harness that creates disposable cells/spaces, drives async transactions, injects commit/response-loss and outbox failures, freezes time for retention/expiry, and checks SQL state after every failure. A passing in-memory test does not prove Postgres isolation, Hyperdrive cache behavior, auth race fencing, HTTP/MCP equivalence, Cloudflare delivery or snapshot export. Owners: STA-5 (transactions), STA-6 (auth/routing), STA-7/8 (schema/query), STA-12/14 (projections), STA-9/10/11 (transport/UI). Run with isolated test credentials and record real provider/region/version evidence separately.
